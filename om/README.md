# OpenMacro templates, as a course

Seventy-six ready-made macros, written in the OpenMacro language and ordered from the smallest possible macro to
webhook-driven bots. Read them top to bottom: each one adds about one idea to the ones before it, and every file opens
with a `// Teaches:` comment saying which. They are the same automations the Store has always offered; installing one from the
Store gives you exactly this source.

This file is generated by `tools/gen_readme.py` from `catalog.json` and the file headers. Do not edit it by hand.

## How to read and try them

```
om check  templates/battery/low-battery-warning.om --caps docs/lang/capabilities/sample.json --caps docs/lang/capabilities/legacy-core.json
om fmt    templates/battery/low-battery-warning.om            # canonical layout; --check / --write
om dump   templates/battery/low-battery-warning.om --view manifest --caps ...   # the permissions it needs
om run    templates/messaging/sms-to-email.om --caps ... --macro "Forward SMS to email" \
           --trigger sms.received --event sender=+1555 --event body=hello --trace
```
Templates that `include "@openmacro/..."` also need `--pkgs <dir>`: install the packages from `templates/packages/` with
`om pkg install templates/packages/<name> --to <dir> --caps ... --approve --trust-publisher`.

## Conventions

- **`// Teaches:`** the first comment of every file. Comments explain *why*; the code says what.
- **`const`** at the top holds the values you are expected to edit (an address, a Wi-Fi name, a package id).
- **`// GAP TG-nn`** marks a step that is a placeholder because the app has no such trigger or action yet. The macro still
  checks and reads as intended; `docs/lang/TEMPLATE-GAPS.md` explains each gap and which templates need it. 42 templates have none.
- **One macro per file**, in the folder of its Store category (`battery/`, `time-focus/`, `car-audio/`, ...).
- **Packages** (`packages/`) are small libraries the templates `include`: typed helpers over HTTP and JSON, each declaring
  the permissions it reaches. The Store installs them before the template and asks for their settings (tokens, addresses).

## The Store build

`om store build templates --caps ... --out templates/store --base-url <url> --catalog templates/catalog.json` verifies every
package and template, then writes `index.json` (each entry lists the permission surface the checker *computed* and the exact
package versions it includes), one `.ompkg` per package and one `.om` per template. `tools/build-store.sh` runs it with the
settings the repository uses; `TemplatesTest` fails when `store/` is stale. Sign the index with `om pkg sign` before publishing.
